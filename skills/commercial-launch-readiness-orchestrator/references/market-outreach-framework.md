# Market And Outreach Framework

Use this reference after the repo-truth pass. Market claims must be based on current credible sources, not feature enthusiasm.

## Ranking Rule

Rank by buyer pain plus repo proof plus urgency. Do not rank by novelty alone.

Primary score:

`buyer pain x urgency x proof fit x reachable buyer x willingness-to-pay signal`

Lower the score for unsupported claims, crowded substitutes, weak proof, unclear buyer, long procurement cycles, or missing compliance evidence.

## Top 10 Pain-Point Discovery

For each pain point, collect:

| Field | Required Evidence |
|---|---|
| Pain point | Concise buyer-language problem. |
| Affected buyer | Role, team, company type, or market segment. |
| Current workaround | Spreadsheet, manual process, agency, incumbent tool, internal build, or no solution. |
| Cost of pain | Time, money, risk, compliance exposure, missed revenue, churn, or strategic delay. |
| Source evidence | Current links from credible sources, buyer forums, analyst reports, job posts, reviews, docs, filings, or support threads. |
| Willingness-to-pay signal | Budget owner, paid incumbent, regulatory mandate, active hiring, RFP/procurement signal, or urgent operational trigger. |
| Repo proof fit | Which implemented feature or verified workflow addresses the pain. |
| Confidence | 1-5 with reason. |

## Competitor And Substitute Analysis

Include direct competitors and substitutes:

- Direct SaaS competitors.
- Incumbent platforms.
- Consulting or agency workaround.
- Internal spreadsheet/manual workflow.
- Open source tools.
- "Do nothing" and delayed adoption.

For each, compare:

- Target buyer.
- Core promise.
- Pricing or pricing proxy.
- Proof standard buyers expect.
- Where the audited repo is stronger.
- Where the audited repo is weaker.
- Switching or adoption friction.

## Target Customer Ranking

Produce a top 10 table:

| Rank | Account/Segment | Buyer Pain | Trigger | Decision Maker | Outreach Angle | Proof To Show | Confidence |
|---:|---|---|---|---|---|---|---:|

Account entries can be named companies only when source evidence supports relevance. Otherwise use narrow segments such as "Series A B2B SaaS teams with SOC2 pressure" or "regional logistics firms with customs filing delays."

## Outreach Plan

Create a 30/60/90 plan:

- 0-30 days: validate pain, run founder-led demos, collect objections, tighten proof pack, avoid unsupported scale claims.
- 31-60 days: run targeted pilots, measure activation and buyer feedback, create case-study style evidence if allowed.
- 61-90 days: move strongest segment toward paid pilot or annual contract, formalize pricing, support, security docs, and onboarding.

## Outreach Scripts

Include three variants:

- Email: short, pain-led, proof-led, single ask.
- LinkedIn: shorter, human, no hype, ask for relevance check.
- Demo opener: 3-minute narrative tied to the buyer's current workflow and one measurable outcome.

Each script must include:

- Buyer-specific pain.
- Why now.
- Proof artifact or demo evidence.
- Low-friction ask.
- Caveat if the product is pilot-only.

## Objection Handling

Cover likely objections:

- "We already use X."
- "Is this secure enough?"
- "Can this integrate with our stack?"
- "How long does onboarding take?"
- "What proof do you have?"
- "Who supports this?"
- "What happens if it is wrong?"
- "Can procurement approve this?"

## CRM And Export Schema

Use this schema for outreach tracking:

| Field | Notes |
|---|---|
| account_name | Company or segment name. |
| website | Source URL. |
| buyer_role | Target decision maker or champion. |
| pain_point | Primary pain matched to the repo. |
| trigger | Recent event, hiring signal, regulation, incident, growth, or workflow pressure. |
| proof_asset | Demo, test result, report, screenshot, case study, or repo artifact. |
| outreach_angle | One-sentence angle. |
| status | researched, contacted, replied, demoed, pilot, closed, rejected. |
| next_action | Concrete next step and date. |
| objections | Buyer objections and responses. |
| confidence | 1-5. |
