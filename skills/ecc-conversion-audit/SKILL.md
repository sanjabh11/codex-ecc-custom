# Conversion Audit

## Objective

Find conversion friction while separating heuristic review from measured uplift.

## Operating Contract

1. Read the route or artifact, target audience, funnel stage, traffic source, primary action, and current analytics evidence.
2. Audit message match, value clarity, proof placement, objection handling, CTA hierarchy, form friction, privacy, accessibility, performance, and instrumentation.
3. Separate observed defects, heuristic risks, unknowns, and measured problems.
4. Rank fixes by expected impact, confidence, effort, and claim risk; keep the smallest viable change first.
5. Define the before/after metric and guardrails. Do not promise conversion lift from a static audit.
6. Return a scored audit, prioritized remediation list, and experiment plan.

## Required Outputs

- conversion scorecard
- evidence/unknown ledger
- prioritized fixes
- measurement plan

## Proof and Safety

- Use the proof buckets `hosted/live`, `local`, `repository artifact`, `candidate/shadow`, and `roadmap`.
- Cite the source of load-bearing claims and label inference, uncertainty, contradiction, and stale evidence.
- Return `unavailable` when required data, tools, consent, or credentials are missing.
- Default external communications and system mutations to draft or dry-run. Require explicit approval in the current turn before any send, enrollment, publish, payment, CRM write, or production action.
- Preserve product-specific safety, scientific, regulatory, privacy, and buyer-evidence gates.
- Do not add dependencies for a text-and-evidence workflow.
