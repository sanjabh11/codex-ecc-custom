# Lead Dossier

## Objective

Create decision-ready account research before any outreach is drafted.

## Operating Contract

1. Read the product proof boundary and define the target role, organization type, geography, pain hypothesis, and disqualifiers.
2. Use only exposed, authorized sources. Record URL, date, source tier, and a concise evidence excerpt or summary.
3. Map organization, stakeholders, triggers, likely pain, alternatives, procurement constraints, and proof needs.
4. Score fit, urgency, reachability, evidence quality, and risk separately; never invent emails, relationships, or intent.
5. Redact personal data and keep sensitive source material outside the repository.
6. Return a dossier and recommended next action: research more, draft outreach, request an introduction, hold, or reject.

## Required Outputs

- source ledger
- account and stakeholder map
- scored dossier
- bounded next action

## Proof and Safety

- Use the proof buckets `hosted/live`, `local`, `repository artifact`, `candidate/shadow`, and `roadmap`.
- Cite the source of load-bearing claims and label inference, uncertainty, contradiction, and stale evidence.
- Return `unavailable` when required data, tools, consent, or credentials are missing.
- Default external communications and system mutations to draft or dry-run. Require explicit approval in the current turn before any send, enrollment, publish, payment, CRM write, or production action.
- Preserve product-specific safety, scientific, regulatory, privacy, and buyer-evidence gates.
- Do not add dependencies for a text-and-evidence workflow.

## Routing

Use adjacent skills rather than reproducing them: `lead-intelligence`, `ecc-niche-positioning-audit`. This skill owns only the closed capability described above.
