# Value Pricing

## Objective

Translate buyer outcomes and evidence into offers without inventing ROI or willingness to pay.

## Operating Contract

1. Read the validated segment, buyer job, alternatives, procurement path, delivery cost, and available outcome evidence.
2. Separate value hypothesis, cost floor, reference price, willingness-to-pay evidence, and unverified assumptions.
3. Build good/better/best or pilot/standard/enterprise packages with explicit scope, evidence, exclusions, and success criteria.
4. Model ranges and scenarios; never present estimated savings, risk reduction, or ROI as guaranteed.
5. Use call or discovery evidence to update objections and pricing hypotheses, not to silently change public claims.
6. Return a pricing brief plus the cheapest experiment that can falsify the key willingness-to-pay assumption.

## Required Outputs

- value hypothesis
- tiered package table
- assumption and risk ledger
- pricing validation experiment

## Proof and Safety

- Use the proof buckets `hosted/live`, `local`, `repository artifact`, `candidate/shadow`, and `roadmap`.
- Cite the source of load-bearing claims and label inference, uncertainty, contradiction, and stale evidence.
- Return `unavailable` when required data, tools, consent, or credentials are missing.
- Default external communications and system mutations to draft or dry-run. Require explicit approval in the current turn before any send, enrollment, publish, payment, CRM write, or production action.
- Preserve product-specific safety, scientific, regulatory, privacy, and buyer-evidence gates.
- Do not add dependencies for a text-and-evidence workflow.
